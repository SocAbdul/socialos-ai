# Cloudflare R2 staging configuration

Status: manual cutover plan only. No Cloudflare API call or bucket creation is performed.

## Planned configuration

1. Create a private staging-only bucket after explicit approval.
2. Create a bucket-scoped API token limited to object read/write for that bucket.
3. Set `S3_ENDPOINT_URL=https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, `S3_MEDIA_REGION=auto`, the bucket name and access credentials only in the host secret file.
4. Place a dedicated staging media hostname in front of R2 and set it as `S3_MEDIA_PUBLIC_BASE_URL`.
5. Never expose the S3 API endpoint as the user-facing media URL.

## CORS and object policy

Allow only the stable staging origin. Permit `PUT`, `GET` and `HEAD`; allow only upload headers used by SocialOS (`Content-Type` and `x-amz-meta-sha256`), expose `ETag`, and keep preflight caching bounded. Do not allow wildcard origins with credentials.

Objects use opaque workspace-scoped keys generated by the backend. The browser receives a short-lived signed upload URL, never R2 credentials. Public delivery is read-only through the media hostname. Treat uploaded objects as immutable; use `Cache-Control: public, max-age=31536000, immutable` when the object key is content-addressed or unique. Never enable bucket listing.

## Validation after authorization

- Upload a non-sensitive test image using the application flow.
- Confirm direct unauthenticated write/list operations fail.
- Confirm the public media URL reads the object and has the expected MIME type/cache header.
- Confirm API credentials cannot access other buckets.
- Rotate the token and prove the old credential no longer works.

Until these checks are executed, R2 remains `CONFIGURED_NOT_VERIFIED`.
